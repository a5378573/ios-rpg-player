# 引擎接入（已完成）

这篇记录 XP / VX / VX Ace 的原生引擎是怎么真正链进 App 的，以及为什么只能这么做。
写下来是因为其中有几个坑，换个时间重新踩一遍的成本很高。

## 结论先说

用的是上游发布的**预编译 core**，不是自己从源码编：

| 组件 | 来源 | 版本 |
|---|---|---|
| 引擎核心 + 三个 Ruby binding + 全部依赖库 | `mateo-m/mkxp-z-apple-mobile` release | `v24`（commit `047c865`） |
| ANGLE（GLES on Metal） | `mateo-m/empo-deps` release | `angle-2026-11-19` |

下载、校验、解压由 `Scripts/fetch_engine.sh` 完成，产物落在 `Vendor/`（不入库，267 MB）。

不自己编的原因很直接：这条链路要编三份 libruby（1.8 / 1.9 / 3.1）、SDL2、pixman、OpenAL、physfs、FreeType、FluidSynth、ANGLE，还要用 `ld -r --unexported_symbols_list` 把每份 Ruby 的符号藏起来只留一个入口。上游 CI 已经在做这件事，且发的是带 sha256 的固定包，没有理由重做一遍。

**为什么不做成"编源码"的脚本**：源码构建需要 macOS + 完整 Xcode + 三份 Ruby 交叉编译工具链，跑一次一个多小时；预编译包 112 MB，拉下来就能链。工程里保留 `Vendor/mkxp/MANIFEST`，升级时对得上 commit 和 RGSS 掩码。

## 包里的东西

```
Vendor/mkxp/
├── MANIFEST                 tag / commit / angle / rgss_mask
├── LINK                     链接参数原文（本工程抄进 Config/Engine.xcconfig）
├── include/app_bridge.h     宿主唯一要看的头文件
├── assets/                  shader、字体、SoundFont、CA 根证书、preload/postload 脚本
├── iphoneos/
│   ├── lib/                 libmkxpz-core.a、mkxp{18,19,31}-merged.o、20 个依赖库
│   └── ruby-stdlib/         1.8 / 1.9.1 / 3.1.0 三套标准库
└── iphonesimulator/         同上
Vendor/angle/<sdk>/{lib,include}   libANGLE_static.a、libEGL_static.a、libGLESv2_static.a
```

`LINK` 里有两处相对路径（`lib/...`、`-Llib`），`Config/Engine.xcconfig` 把它们换成了 `$(SRCROOT)` 绝对路径，其余原样照抄。**升级引擎版本时，一定要用新包的 `LINK` 重新核对 xcconfig**，库列表会变。

## 链接上的三个关键点

**1. `-force_load` 必须加。**
链接器默认只挑被引用的目标文件，而 `app_bridge.h` 里的函数宿主是间接调用的，大部分没有静态引用，不加 `-force_load` 会被整个裁掉，运行时报符号缺失。

**2. 三个 `mkxpNN-merged.o` 要整份链进来。**
它们各自是一份完整的 Ruby VM + binding，符号被 `ld -r --unexported_symbols_list` 藏起来了，只导出一个 `_mkxp_get_script_binding_NN`。引擎启动时按宿主选的版本分派。少链一个，对应的 RPG Maker 版本就起不来。

**3. 运行时资源必须落在 `.app` 根目录。**
引擎用 `dladdr` 找自己旁边的 `Assets.bundle` 和 `Ruby/`。工程里用 `postBuildScripts` 把 `Vendor/mkxp/assets` 拷成 `Assets.bundle`、把 `ruby-stdlib` 拷成 `Ruby`，直接放进 `${UNLOCALIZED_RESOURCES_FOLDER_PATH}`（iOS 上就是 `.app` 根）。名字不能改，也不能被 Xcode 拍平。

## 宿主与引擎的接口

真正的 C 接口在 `app_bridge.h`，但 Swift 不直接碰它，中间隔了 `Sources/Engines/Host/RPGEngineHost.{h,m}`。原因有两个：一是启动顺序有严格要求，二是回调在引擎线程触发、错误弹窗还会阻塞引擎线程，这些细节集中在一处比散在 Swift 里可靠。

### 启动顺序（照抄上游 GameCore 的约定）

```
setDebugLogPath
  → setLauncherIdentity / setCABundlePath
  → setSetting × n（rubyVersion / syntaxTransform / postloadScripts …）
  → applySessionConfig
  → resetSessionState
  → setGamePath
  → run_app
```

顺序错了会出现「配置被复位」「引擎一直卡在等游戏路径」这类难查的问题。

### 线程：必须在主线程，且只能从 run loop callout 调

`mkxp_run_app()` 会**占住调用线程直到游戏结束**。头文件写得很明确：

> 不要从主线程 dispatch 队列的 block 里调用。它会一直占着线程，队列永远不会排空，RGSS 线程在第一次 `mkxp_getScreenScale` 处死锁。

所以 `MkxpSession` 用 `RunLoop.main.perform { rpg_run() }` 起引擎——这是 run loop 的定时器回调，不是 dispatch block。

代价是：**引擎跑起来后 SwiftUI 不再刷新**。游戏内的虚拟手柄因此是 UIKit 的 `GamepadOverlayView`，挂在 `mkxp_getGameWindow()` 返回的 `UIWindow` 上。引擎内部调用 `SDL_iPhoneSetEventPump(SDL_TRUE)`，由 SDL 在自己泵事件时驱动 UIKit，覆盖层才能正常绘制和响应触摸。

### 回调与阻塞

| 回调 | 线程 | 宿主必须做什么 |
|---|---|---|
| 引擎终止 | 引擎线程 | 只记日志；`rpg_run()` 返回后统一收尾 |
| 错误 / 提示 | 引擎线程 | 弹窗，关闭时调用 `rpg_dismiss_error()` / `rpg_dismiss_info()` |
| 帧渲染 | 引擎线程 | 本工程暂未使用 |

错误弹窗是**阻塞式**的：引擎线程停在 `mkxp_presentErrorAndWait` 里等宿主确认。宿主忘了回调 dismiss，整个引擎就永久挂住。`RPGEngineHost.m` 里对「找不到可present的控制器」也做了兜底，直接 dismiss，避免死锁。

### Ruby 版本

| 引擎 | RGSS | Ruby | binding |
|---|---|---|---|
| XP | RGSS1 | 1.8 | `mkxp18-merged.o` |
| VX | RGSS2 | 1.9 | `mkxp19-merged.o` |
| VX Ace | RGSS3 | 3.1 | `mkxp31-merged.o` |

XP 的老游戏用真 1.8 解释器跑，不是靠 Ruby 3 的语法兼容补丁硬扛——这点对脚本写得随意的中文老游戏尤其重要。

## 一个进程只能一个会话

这是 CRuby 的限制，不是实现偷懒：`ruby_init()` 每进程只能成功调用一次，SDL / EGL / OpenAL 的上下文同样跟着 Ruby VM 存活。上游的做法是整套资源全程复用，而不是销毁重建。

于是产生了产品上的硬约束：

- 退出游戏后，Ruby VM 状态无法可靠复位；
- 想玩下一个 XP/VX/VA 游戏，必须从后台划掉 App 再重开；
- 同类应用 Empo 的公开说明里写着同样的限制，并明确说是「Ruby 无法可靠清理状态」导致的。

UI 上已经在会话结束时弹窗说明，`MkxpSession.hasRunBefore` 会拦住二次启动并给出提示，而不是让玩家点进去黑屏。

## 2000 / 2003 为什么没接

EasyRPG Player 官方支持 Windows / Linux / macOS / Android / 主机 / 浏览器，**唯独没有 iOS 目标**。作者在 0.6.1 的发布说明里写得很直白：

> iOS（唯一一个我们还没真正支持的平台，因为缺触摸 UI）

社区有第三方做的 iEasyRPG，但那是别人维护的私有移植，没有可复用的构建产物。要接进这个 App，等于自己写一套 iOS 平台层（SDL 窗口、音频会话、触摸 UI、文件访问），工作量不比接一次 mkxp 小。所以这一版先不碰，播放页会明确告诉玩家「需要 EasyRPG，当前版本未提供」。

## 想自己重编引擎

只有在改引擎源码时才需要，流程在上游 README 里：

```bash
git clone https://github.com/mateo-m/mkxp-z-apple-mobile
cd mkxp-z-apple-mobile
tools/fetch-deps-ios.sh          # 拉预编译依赖
tools/build-core-ios.sh --sdk iphoneos --arch arm64 --min-os 17.0 ...
tools/build-binding-ios.sh ...
tools/package-ios.sh             # 产出 mkxp-z-ios.tar.gz
```

拿到 tarball 后，把 `Scripts/fetch_engine.sh` 里的 `ENGINE_SHA256` 和版本换成自己的（或本地放到 `Vendor/` 下），再跑一次脚本即可。`MANIFEST` 里的 `rgss_mask` 决定 Xcode 侧报告的 RGSS 支持位，改成 7 才代表三个版本齐全。

## 排错顺序

游戏起不来时按这个顺序看：

1. `Documents/Logs/<游戏目录名>.log` —— 引擎自己的日志，`mkxp_setDebugLogPath` 指定的；
2. Xcode 控制台里 `[mkxpz-core]` 开头的行 —— 初始化到哪一步；
3. 检查 `RPGPlayer.app/Assets.bundle` 与 `RPGPlayer.app/Ruby` 是否存在；
4. `nm RPGPlayer.app/RPGPlayer | grep mkxp_get_script_binding` —— 应该有 3 个；
5. 确认游戏目录里是 `.rxdata` 而不是 `.rvdata2`（后者是 VX Ace 的，选错引擎版本会读不到数据）。
